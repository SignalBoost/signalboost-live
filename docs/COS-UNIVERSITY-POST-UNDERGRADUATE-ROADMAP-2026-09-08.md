# COS University — Post-Undergraduate Roadmap

Date: 2026-09-08
Status: accepted forward implementation sequence after the A/A+ Generalist Graduation Gate

## Controlling principle

The University is an education engine whose claims must be earned by independent evidence. Degrees never expand execution authority. Each later layer must preserve learner/examiner separation, hidden evaluation material, auditable evidence, current-competence tracking, and Production proof where the capability operates in Production.

## Sequence

1. **Master’s specialist programs**
   Build complete graduate programs on top of an awarded A/A+ undergraduate credential: program-specific admissions, curricula, deliberate practice, independent specialist exams, cross-domain transfer, verified practical/Production work, capstone, immutable credential, current competence and recertification.

2. **PhD / research programs**
   Add research methodology, primary-literature review, hypothesis generation, experimental design, replication/reproducibility, adversarial peer criticism, novelty tests, negative-result handling, research artifacts and host-controlled research graduation criteria.

3. **Faculty architecture**
   Separate learner, tutor/professor, examiner and peer/critic roles. Faculty agents may teach, challenge and evaluate only within explicit role boundaries. The learner never receives hidden examiner seeds/rubrics/answers and cannot issue its own academic credit.

4. **Metacognitive learning optimization**
   Empirically compare study methods using controlled outcomes: source classes, explanation styles, retrieval, deliberate practice, examples, counterexamples, spaced retest, tutor critique, peer critique and tool/lab work. Teaching strategy changes only from measured transfer/retention evidence, not model preference.

5. **Generalize University beyond COS**
   Replace COS-specific student assumptions with an explicit tenant/student/agent identity, program enrollment, capability baseline, evidence ledger and policy boundary. COS becomes one student/orchestrator using the same education engine rather than the engine itself.

6. **Commercial Portable University**
   Package the generalized engine as a deployable/licensable product with configurable curricula, model/runtime adapters, private data boundaries, offline/private deployment options, evidence exports and organization-owned policies.

7. **Enterprise hardening and proof**
   Add multi-tenancy, RBAC, privacy/data-classification controls, academic-integrity controls, auditability, key/secret isolation, private deployments, backup/restore and DR, security validation, load/reliability evidence and procurement-grade documentation.

8. **External-agent pilot**
   Select another AI/agent; establish a frozen baseline; enroll it; educate it through the same engine; use unseen independent post-training evaluations; demonstrate statistically and practically meaningful before-vs-after improvement without leaking test material.

9. **Commercial validation**
   Run a real customer/enterprise pilot with agreed success metrics and baseline. Attribute measurable improvement to the University through controlled evidence, document operational value/cost, and obtain customer acceptance evidence.

## Dependency rule

Do not jump directly to commercial packaging and call the education engine complete. The dependency chain is:

Undergraduate proof → Master’s proof → research/faculty/metacognition → generalized student engine → portable product → enterprise proof → external-agent pilot → customer validation.

Parallel work is allowed where it does not weaken academic integrity or create duplicate state, but later commercial claims must not outrun the evidence from earlier layers.
