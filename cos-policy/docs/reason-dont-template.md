# Reason with evidence. Do not precode questions.

COS is a neural reasoner, not a library of topic-specific answer keys. The product should improve the evidence and control boundaries around the model without replacing inference with a growing set of hand-written semantic rules.

## What failure looks like

A retrieval-shaped answer is not reasoning. The failure pattern is:

1. Search the user’s wording.
2. Read a small set of snippets.
3. Repeat their statistics or headlines in retrieval order.
4. Treat the source set itself as the answer.

The opposite failure is to notice that weakness and add a hand-written paragraph for that topic. That creates an FAQ system: every new subject requires another template, another exception, and another regression tied to specific vocabulary.

## The intended architecture

For ordinary empirical and analytical questions:

1. **The user supplies the proposition.** COS determines what must be established to answer it.
2. **Retrieval supplies evidence.** Current or volatile facts are searched live; stable internal facts use governed internal sources.
3. **The neural reasoner interprets the evidence.** It identifies what each item measures, keeps unlike measurements separate, weighs methodological fit, and infers only what the evidence supports.
4. **The control plane verifies boundaries.** Deterministic code checks freshness, source authority, citation IDs, arithmetic, safety, authorization, system-of-record integrity, and output schemas.
5. **The model synthesizes the answer.** The answer should not mirror retrieval order and should not be generated by a topic-specific formatter before the model sees the evidence.

The control plane may reject an unsupported semantic answer. It should not choose the ordinary semantic conclusion in advance.

## Generalization test

Do not certify a repair only on the prompt that exposed it. Use unseen questions across unrelated domains and ask whether the same method holds:

- Does the model identify what the evidence actually measures?
- Does it keep different populations, denominators, windows, comparison bases, and controls distinct?
- Does it distinguish observation from causal explanation?
- Does it use the strongest relevant evidence rather than every retrieved result?
- Does it state exactly what remains unverified instead of substituting a nearby claim?
- Does it reach the conclusion through the same general reasoning procedure without a new topic rule?

Pass means the behavior transfers to questions that were never named in the policy. Fail means the system needed a keyword, canned first paragraph, or domain-specific semantic branch to produce the answer.

## What deterministic code is for

Deterministic code is appropriate where correctness is itself deterministic or where it defines a boundary around the reasoner: calculations, syntax, permissions, safety gates, provenance, exact source requirements, schema validation, cache keys, system-of-record reads, and evidence-grounding checks.

It is not a replacement for neural inference on an ordinary evidence question merely because a regex can recognize the topic.

## Review rule

A proposed COS repair should be rejected if it fixes an ordinary semantic question by adding a topic-specific answer paragraph, keyword-to-conclusion mapping, or retrieval-order formatter when the same defect can be fixed by improving evidence quality, reasoning instructions, or deterministic validation boundaries.
