# Builder per-run inference budget

This patch implements budgeting in the existing TypeScript Builder V2, not the separately described Python/mock prototype. It is source/test evidence until the migration and exact application revision are deployed and observed.

The enqueue boundary parses the user's dollar cap into integer nanodollars, overwrites caller-supplied budget metadata, and rejects capped legacy/platform-repair jobs. The worker scopes V2 model and tool execution to the original job creation time plus its requested runtime. Resumed claims inherit the same deadline and ledger; they are not new attempts.

Both configured inference and built-in assigned-model transports reserve before physical model HTTP dispatch. Supported requests are DeepInfra's standard, non-streaming, text-only chat completions with a public token tariff and declared context limit. Each reservation covers the entire published context at the input rate plus the requested output ceiling at the output rate, rounded upward. This is deliberately conservative. Unknown prices, unsupported providers/tiers, multimodal requests and unpriced GPU wake/probe paths fail closed; no provider is silently assumed free. Existing model assignments, approvals and stricter Harness budgets remain authoritative.

The service-only PostgreSQL ledger locks the job and budget row, validates user/claim generation, and atomically denies reservations when accounted spend plus outstanding reservations plus the next bound would exceed the original cap. It rejects cap/deadline resets and duplicate call IDs. Token usage settles once; missing usage or lost responses retain the full reservation. A recorded cost exceeding its quote blocks subsequent calls. Reported provider estimates are saved separately from conservative accounting. Published provider tariff/token contracts bound the reservation; this is not a guarantee against a provider violating its own tariff or an independently billed GPU/deployment invoice.

The saved result and History reply include the cap, accounted spend, pending reservations and reserved model-call count. A reservation is a dispatch authorization, not proof that the provider received or executed a call (a worker may die between reservation and HTTP). No costs or calls are invented when evidence is missing. This cap covers model inference only, not repository hosting, Vercel Sandbox or preview compute fees.

Migration: `saas/supabase/migrations/20261019201138_builder_inference_run_budget.sql`. Both tables have RLS and no client policies; tables/functions are restricted to service_role. Apply this additive schema before deploying the guarded worker. Missing schema fails closed before paid dispatch.

No-cost regression coverage uses actual PostgreSQL through PGlite and the committed migration, with explicitly fake provider responses: pre-dispatch tiny-cap denial, concurrent reservation contention, resume/lease loss, idempotent settlement, lost/missing usage, deadline expiry and active-request abort, provider ceiling breaches and client-role denial. The real enqueue, assigned-model transport and agent retry boundaries are also exercised. These tests are not live inference or repository/PR/deployment acceptance.
