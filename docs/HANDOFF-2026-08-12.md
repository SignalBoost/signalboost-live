## What merged in the latest sequence

### COS knowledge / cache / provenance

The knowledge-use sequence described in the earlier version of this handoff has now materially advanced:

- **PR #1128** — automatic learned-document → structured-fact promotion through the existing grounded local fact extractor.
- **PR #1131** — 768-dimensional embeddings and semantic nearest-neighbor retrieval for `cos_knowledge_facts`; newly promoted facts are embedded with the existing local `nomic-embed-text` path, and older facts are incrementally backfilled.
- **PR #1134 / #1135** — policy-versioned, age-bounded answer cache plus cache-origin provenance and the TypeScript verdict fix. Old answers produced under a different prompt/model/gate are no longer silently reused forever.
- **PR #1133** — provenance schema v2 and explicit evidence funnel telemetry: `retrieved → relevant → selected → injected → cited`. Cache hits now distinguish current-request execution from the turn that originally generated the cached answer.
- **PR #1136** — confidence evidence credit is earned only by cited Knowledge Graph + learned-corpus grounding. Merely retrieving/injecting many unused items no longer raises the evidence ceiling. The model-only ceiling remains 0.78, above the default 0.72 gate.

The repeated multi-tenant SaaS benchmark exposed the original problem clearly: a semantic cache hit could bypass Qwen correctly, but on a fresh reasoning turn the learned corpus could be retrieved without demonstrably contributing. The system now records exactly where evidence drops out instead of collapsing retrieval and use into one number.

## Self-Healing Supervisor monitoring

The product is proactive and monitor-capable, not merely reactive to an external monitoring product. Native monitoring is default-capable; buyer monitoring may coexist in hybrid mode or replace it by explicit buyer choice.

Existing external monitoring adapters remain available for Datadog, PagerDuty, AWS CloudWatch/EventBridge, Prometheus Alertmanager, Splunk, Azure Monitor, Grafana Alerting and Google Cloud Operations. They remain `staged`, not `certified`, until real-provider validation exists.

## Safety / automation doctrine

Routine remediation may be automatic only when explicitly registered and pre-authorized within bounded capability/resource/method/parameter/reversibility/execution limits. Consequential, destructive, financial, credential/security and otherwise approval-required operations continue through the signed approval path. Monitoring itself remains observation-only and creates no mutation authority.
